Ce conține fiecare pagină din raportul Power BI

Patru pagini complete, fiecare cu întrebări de business și vizuale potrivite. Model: Vanzari + Dim_Date, Dim_Clienti, Dim_Produse, Dim_Magazine. Fără măsuri DAX — doar câmpuri trase în vizuale; Power BI folosește agregări implicite (Sumă, Medie, Număr) după ce ai curățat tipurile în Power Query.

Înainte de raport

Curățare · Power Query

Ghid complet · Vanzari_s5_murdar.xlsx

Lucrezi tabel cu tabel, apoi construiești modelul. În raport, timpul vine din Dim_Date; în fact rămân Data_Facturare (audit) + ID_Date (FK).

01 Vanzari 02 Dim_Date 03 Dim_Clienti 04 Dim_Produse 05 Dim_Magazine 06 Model & verificare
Ordinea obligatorie
  1. Dim_Date → Dim_Clienti → Dim_Produse → Dim_Magazine (chei curate, unice).
  2. Vanzari (tipuri + ID-uri numerice, fără null).
  3. Model view — patru relații many-to-one; apoi paginile de raport.

1 · Vanzari

Export ERP · ordine coloane: ID_Date, ID_Client, ID_Produs, ID_Magazin, Data_Facturare, apoi măsuri

A · Structură (rânduri)

  1. Elimină primele 2 rânduri (titlu + subtitlu export).
  2. Use First Row as Headers.
  3. Elimină ultimul rând (Total linii export…).
  4. Remove Blank Rows unde întreg rândul e gol.

B · Dată facturare & cheie calendar

  1. Data_Facturare: Trim → tip Date, locală Română (România) (dd.MM.yyyy).
  2. Date invalide din set (31.02.2024, 2024-13-40): ștergi rândul sau Replace Errors → null, apoi filtrezi null dacă nu vrei linii fără dată.
  3. ID_Date: Trim → Whole Number — FK către Dim_Date[ID] (nu recalcula ID din dată dacă sursa îl dă deja).

C · Cantitate & procente

  1. Cantitate: Trim → Replace buc, buc., BUC → gol → , → . la zecimale → Decimal Number.
  2. Discount_Pct, Cota_TVA: Whole Number (în sursă sunt deja numere, fără %).

D · Sumă (deja numeric în Excel)

Pret_Lista, Valoare_Neta, Valoare_TVA, Valoare_Totala — nu au RON sau text; nu folosi Trim aici.

  1. Verifică tipul: Decimal Number (sau Fixed Decimal). Dacă Power Query le-a citit greșit, schimbă tipul o singură dată — fără Replace pe text.
  2. În Model sau pe coloană: format Currency, monedă RON (doar afișare).

E · Text & duplicate

  1. Canal_Vanzare, Status_Plata, Moneda, UM: Trim → Text (ex. Online → Online).
  2. Duplicat intenționat: un rând e copiat — la final Remove Duplicates pe toate coloanele dacă vrei fact fără dubluri.

F · ID-uri fact (înainte de Close & Apply)

  1. ID_Client, ID_Produs, ID_Magazin, ID_Date: Trim → Whole Number.
  2. Elimină rândurile cu oricare dintre aceste ID-uri null sau gol (inclusiv după erori la conversie).
  3. Seturile cursului nu conțin ID care lipsesc din dimensiuni — după pașii de mai sus, FK-urile se potrivesc modelului star.

2 · Dim_Date

2022–2025 · ID + atribute calendar · fără coloană sărbători

  1. Elimină 2 rânduri titlu/notă → header: ID, Data, An, Trimestru, Luna, Luna_Nume, …
  2. ID: Whole Number, unic (PK).
  3. Data: Trim → Date, locală România; serial Excel / yyyy/mm/dd → corectezi sau Replace Errors.
  4. Fix punctual: 32.01.2022, celule goale.
  5. An, Luna, Trimestru, Luna_Nume, Zi_Saptamana, … — tip corect; sortare grafice lună după Luna.
  6. Zi_Lucratoare: Da/Nu; YES → Da sau Nu.

3 · Dim_Clienti

CRM · 2 rânduri junk · tip client inconsistent · duplicat ID 36

  1. Elimină junk → header cu ID, Denumire, Tip_Client, …
  2. ID: Trim → Whole Number; duplicat 36 → Remove Duplicates pe ID (Keep First).
  3. Tip_Client: unifică PJ/PF vs Persoana Juridica/Fizica.
  4. Oras, Regiune, Email: Trim; text NULL → null.
  5. Data_Inregistrare: Date, locală RO.
  6. NPS_Ultim: fără /10; virgulă zecimală → punct → număr.

4 · Dim_Produse

Header dublu · categorie fill-down

  1. Elimină rând gol + rând header vechi (Cod produs, Cat.).
  2. Corectează rândul cu categorie/subcategorie inversată → Fill Down pe Categorie.
  3. Pret_Catalog: Decimal Number (număr în sursă).
  4. ID, Greutate_Kg: numere; Activ: Da/NU; Nume_Produs, SKU: Trim.

5 · Dim_Magazine

Abrevieri regiune · lat/long cu virgulă · ID 11 duplicat

  1. Elimină rând titlu → header.
  2. Regiune: NW, SE, B-IF → nume complete.
  3. Latitudine, Longitudine: virgulă → punct → Decimal.
  4. Suprafata_mp: fără mp → Whole Number.
  5. ID 11 duplicat: dedupe sau redenumește magazinul înainte de model.

Relații (Model view): Fact[ID_Date] → Dim_Date[ID] · Fact[ID_Client] → Dim_Clienti[ID] · Fact[ID_Produs] → Dim_Produse[ID] · Fact[ID_Magazin] → Dim_Magazine[ID]. Toate many-to-one, single direction de la fact la dim.

Orfani — nu în model: factul încărcat nu trebuie să conțină FK fără rând în dimensiune. Dacă la raport vezi blank pe denumiri magazin/produs/client, ai ratat filtrarea în PQ — revino la pasul F pe fact.

  1. Checklist final: toate dimensiunile au ID unic, tip număr.
  2. Fact: fără rânduri junk; FK numerice (Trim, fără null); bani și cantități numerice.
  3. Model: 4 relații active; fără warnings de tip „many-to-many” nedorit.
  4. Abia apoi construiești cele 4 pagini de raport (Card, Line, Bar, Matrix…).

Model (Model view): relații many-to-one de la fact la dimensiuni: Vanzari[ID_Date] → Dim_Date[ID], Vanzari[ID_Client] → Dim_Clienti[ID], Vanzari[ID_Produs] → Dim_Produse[ID], Vanzari[ID_Magazin] → Dim_Magazine[ID]. Numele tabelelor în raport pot fi redenumite după import; păstrează aceleași nume de coloane ca în Excel curățat.
