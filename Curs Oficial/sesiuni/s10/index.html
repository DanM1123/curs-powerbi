Import sau DirectQuery?

Care e diferența dintre cele două moduri de încărcare a datelor?

Import copiază datele în model, iar ele rămân cele de la ultimul refresh. DirectQuery nu copiază nimic: trimite o interogare la sursă la fiecare vizual. Azi folosim Import.

De ce un refresh programat?

Ai publicat un raport. De ce nu apar singure datele noi de luna asta?

Raportul publicat conține o copie a datelor de la momentul publicării. Refresh-ul (manual sau programat) reia interogările către sursă și aduce datele noi.

De ce o tabelă de date?

Ce are nevoie Power BI de la calendar ca să meargă SAMEPERIODLASTYEAR?

O tabelă de date cu fiecare zi o singură dată, fără goluri, marcată ca date table. Azi o primim gata făcută, tot ca Dim_Date, dar pe cinci ani.

Partea 2 · Combinarea fișierelor Ideea

Un folder, un fișier nou la fiecare trimestru

Fără folder

    Partea 3 · Model Tabela de date

    Tabela de date: o formulă, în New table

    Modeling → New table, apoi lipiți

    Dim_Data =
VAR _Inceput = DATE ( YEAR ( MIN ( Rezervari[Data] ) ), 1, 1 )
VAR _Sfarsit = DATE ( YEAR ( MAX ( Rezervari[Data] ) ), 12, 31 )
RETURN
ADDCOLUMNS (
    CALENDAR ( _Inceput, _Sfarsit ),
    "An", YEAR ( [Date] ),
    "Trimestru", "T" & QUARTER ( [Date] ),
    "Luna", MONTH ( [Date] ),
    "Luna_Nume", FORMAT ( [Date], "MMMM" ),
    "Zi_Saptamana", FORMAT ( [Date], "dddd" )
)

    Ce face formula

    1. Ia prima și ultima zi din Rezervari[Data] și le extinde la anul întreg: 1 ianuarie – 31 decembrie.
    2. CALENDAR face câte un rând pentru fiecare zi: 365 de rânduri.
    3. ADDCOLUMNS adaugă anul, trimestrul, luna (număr și nume) și ziua săptămânii.

    De ce o tabelă separată: Rezervari are doar zilele cu rezervări, cu goluri. Funcțiile de timp și slicerele pe lună au nevoie de fiecare zi, o singură dată. Marcarea ca tabelă de date și relația se fac pe slide-ul următor.

    Partea 3 · Matrix dinamic Ce construim în Power BI

    Un matrix, trei slicere, 162 de combinații

    În Excel tragi câmpurile unui pivot la Rânduri, Coloane și Valori. Un field parameter face același lucru în raport: e un slicer care schimbă câmpul afișat, nu filtrează valori.

    RânduriParametru Randuri · 9 câmpuri
    CompanieTip companieRutaȚara destinațieClasaCanalTip canalGrupa de vârstăNivel loialitate
    ColoaneParametru Coloane · 3 câmpuri
    TrimestruLunaTip rută
    ValoriParametru Valori · 6 măsuri
    BileteVenit RezervariPret Mediu BiletZile Avans MediuVenit BagajRata Anulare %
    Un singur matrix: 9 × 3 × 6 = 162 de combinațiiCititorul alege din trei slicere, fără să editeze raportul. Fără field parameters ai avea 162 de matrice, sau unul singur, cu câmpuri fixe.

    Ordinea: un parametru conține doar câmpuri și măsuri care există deja. De aceea facem întâi modelul, tabela de date și măsurile, apoi cei trei parametri, apoi matrix-ul.

    Partea 3 · Matrix dinamic Pas cu pas în Power BI

    Apăsați pe fiecare pas

    Home → New measure · tabela Rezervari

    Măsurile de bază

    Bilete = CALCULATE ( SUM ( Rezervari[Nr_Bilete] ),
    Rezervari[Status_Rezervare] = "Confirmata" )

Venit Rezervari = CALCULATE ( SUM ( Rezervari[Valoare_Totala] ),
    Rezervari[Status_Rezervare] = "Confirmata" )

Pret Mediu Bilet = DIVIDE ( [Venit Rezervari], [Bilete] )

    De ce contează: parametrul de valori conține doar măsuri care există deja, deci le facem primele. Numărăm doar rezervările confirmate, pentru că cele anulate nu aduc venit. Pret Mediu Bilet e un raport, nu se poate aduna: de aceea e măsură, nu coloană.

    Home → New measure · tabela Rezervari

    Alte măsuri

    Zile Avans Mediu = AVERAGE ( Rezervari[Zile_Avans] )

Venit Bagaj = CALCULATE ( SUM ( Rezervari[Bagaj_Extra] ),
    Rezervari[Status_Rezervare] = "Confirmata" )

Rata Anulare % = DIVIDE (
    CALCULATE ( COUNTROWS ( Rezervari ), Rezervari[Status_Rezervare] = "Anulata" ),
    COUNTROWS ( Rezervari ) )

    De ce contează: cu cât ai mai multe măsuri, cu atât parametrul de valori e mai folositor. Cititorul alege dacă vrea volum (bilete), bani (venit, bagaj), comportament (cu câte zile înainte rezervă) sau risc (anulări). Setați formatul: procent la Rata Anulare %, o zecimală la medii.

    Parametru Rânduri

    Modeling → New parameter → Fields

    Parametru Coloane

    Mai întâi sortați Luna_Nume după Luna, altfel lunile ies alfabetic. Nume Parametru Coloane, apoi bifați cele 3 câmpuri:

    Parametru Coloane = {
    ( "Trimestru", NAMEOF ( 'Dim_Data'[Trimestru] ), 0 ),
    ( "Luna",      NAMEOF ( 'Dim_Data'[Luna_Nume] ), 1 ),
    ( "Tip rută",  NAMEOF ( 'Ruta'[Tip_Ruta] ),      2 ) }

    De ce contează: coloanele sunt de obicei timpul. Cititorul trece de la o vedere pe trimestre la una pe luni, iar al treilea câmp compară categorii. Păstrați puține câmpuri: coloanele se lățesc repede.
